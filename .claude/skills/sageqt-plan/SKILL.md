# SageQt 개발 계획

## 무엇이 어디에 있는가

| 위치 | 담는 것 | 언제 읽는가 |
|---|---|---|
| 이 파일 | 절차 + **진행 중인 주제 목록** | 작업을 시작 · 재개할 때 |
| `references/Txx-*.md` | 주제 하나의 **구현 지시서** (프롬프트 형식) | 그 주제를 구현할 때, 그 파일 하나만 |
| `docs/plans/done/` | 끝난 주제 파일 (이력) | 이력을 조사할 때만 |
| `docs/decisions/MIGRATION_PLAN.md` | 배경 · 확정 사실 · 결정 기록 · 전역 리스크 | 배경이나 결정 근거가 필요할 때 |

규칙(네이밍 · 구조 · Git)은 각 스킬에 있다. **주제 파일에 규칙을 복사하지 않는다** — 필요한 스킬과 reference 파일을 가리키기만 한다. 복사하면 규칙이 바뀔 때 두 곳이 어긋난다.

## 절차

### 1. 작업을 시작 · 재개할 때
1. 위 목록에서 **선행 주제가 모두 끝난 첫 주제**를 고른다
2. 그 주제 파일 **하나만** 읽는다. 다른 주제 파일은 읽지 않는다
3. 주제 파일의 *시작 전에* 절을 따른다 — 스킬 로드, 결정 대기 확정, 사실 재확인
4. `git-workflow`대로 브랜치를 만든다. 주제 하나가 PR 여러 개로 나뉘면 주제 파일에 PR 단위를 적는다

### 2. 진행하는 동안
- 주제 파일의 작업 체크박스를 갱신한다
- 새로 확인한 사실은 주제 파일의 *확인한 사실*에 적는다 (숫자와 파일 경로로)
- 여러 주제에 걸치는 결정은 `MIGRATION_PLAN.md`의 결정 기록에 적는다
- 이 목록의 상태 칸을 `진행 중`으로 바꾼다

### 3. 주제를 끝낼 때
1. 주제 파일의 *완료 기준*을 하나씩 실제로 확인한다 (추측으로 체크하지 않는다)
2. 주제 파일 끝에 *결과* 절을 추가한다 — 무엇을 했는지, PR 번호, 교훈
3. `git mv`로 주제 파일을 `docs/plans/done/`으로 옮긴다 (첫 완료 때는 폴더를 먼저 만든다)
4. 이 목록에서 그 행을 지운다. 다른 주제의 *선행* 칸에서 그 ID를 지운다
5. 범위 밖으로 남긴 위험은 `debt-log-guard`로 `docs/DEBT_LOG.md`에 기록한다
6. `git-workflow`대로 `docs/decisions/PR_LOG.md`에 기록한다
7. 이 변경은 `docs:` 커밋으로 남긴다

### 4. 주제를 추가 · 분할 · 순서 변경할 때
- 사용자 확인 없이 하지 않는다. 근거를 제시하고 결정을 받는다
- 새 주제 파일은 아래 *주제 파일 형식*을 따르고, 이 목록에 행을 추가한다

### 5. 규칙(skill)을 고친 뒤 (CRITICAL)
진행 중인 **모든 주제 파일**을 다시 본다. 현재 주제만 보고 넘어가지 않는다.
- [ ] 바뀐 규칙 때문에 불필요해진 주제나 작업이 있는가 → 지우고 사유를 남긴다
- [ ] 선행 관계가 뒤집히는가
- [ ] 주제 파일에 적힌 이름 · 경로 · 시그니처가 새 규칙과 맞는가
- [ ] 주제 파일이 가리키는 스킬 · reference 경로가 여전히 있는가
- [ ] `DEBT_LOG` 항목이 가리키는 주제 ID가 여전히 맞는가

## 스킬 구조 원칙

스킬을 새로 만들거나 고칠 때 따른다 (결정 기록 2026-09-23, `MIGRATION_PLAN.md`).
- SKILL.md는 300줄 이하. 세부는 `references/`로 나누고, SKILL.md에서 언제 읽을지를 가리킨다
- SKILL.md에 상황별 요약(작성 · 수정 · 삭제)을 둔다
- 규칙은 한 스킬에만 둔다. 다른 스킬은 그 스킬을 가리킨다

## 주제 파일 형식

주제 파일은 **Claude Code가 그대로 읽고 구현하는 지시서**다. 세션이 바뀌어도 내용이 손상되지 않도록, SageSDI에서 옮길 사실은 값과 경로까지 원문 그대로 적는다.

```markdown
# Txx — <주제>

> 이 파일은 구현 지시서다. 위에서부터 순서대로 읽고 따른다.

## 목표
이 주제가 끝나면 무엇이 되는가. 한두 문장.

## 시작 전에
1. 선행 주제 확인
2. 로드할 스킬과 읽을 reference 파일 (경로로)
3. 결정 대기 항목 — 사용자에게 확정받는다 (선택지와 권장안)
4. 재확인할 사실 — 착수 시점에 다시 실측한다

## SageSDI에서 옮길 것
원본 경로 · 값 · 동작. 바꾸지 않고 옮길 것과, Qt에 맞게 바꿀 것을 구분한다.

## 옮기지 않는 것
무엇을, 왜.

## 함정
MFC → Qt 이관에서 조용히 동작이 바뀌는 지점, 도구 · 환경 주의점.

## 작업
- [ ] PR 단위로 묶은 체크박스

## 완료 기준
세어볼 수 있는 문장. 검증 명령이 있으면 함께.

## 범위 밖
무엇을, 왜, 어느 주제로.

## 확인한 사실
진행 중 새로 확인한 것 (처음에는 비어 있을 수 있다).
```

### 작성 규칙
- **완료 기준은 측정 가능하게** — "3-OS CI가 모두 통과한다", "경고 0". "정리한다" · "개선한다"는 쓰지 않는다
- **SageSDI 사실은 원문 그대로** — 상수 값 · 파일 경로 · 줄 번호 · 동작 순서를 요약하거나 반올림하지 않는다
- **아직 착수하지 않은 주제의 구현 방법은 확정하지 않는다** — 앞 주제의 결과가 뒤 주제를 바꾼다. 옮길 사실과 함정은 지금 적고, 구현 방법은 *시작 전에*에서 정한다
- **범위 밖은 이유와 행선지를 함께** — "안 한다"만 적으면 누락으로 오해한다

## 공통 함정

여러 주제에 해당하는 도구 · 환경 사실이다. 규칙이 아니므로 스킬이 아니라 여기에 둔다.

| 상황 | 주의 |
|---|---|
| SageSDI `.rc` · `.rc2` 읽기 | **UTF-16LE**다. 그냥 grep하면 0건으로 보인다 → `iconv -f UTF-16LE -t UTF-8`로 바꾼 뒤 읽는다 (이 때문에 틀린 사실을 기록했다가 정정한 적이 있다) |
| SageSDI 소스에서 문자열 복사 | UTF-8 BOM · CRLF 파일이 있다 (`SageDefine.h` 등). SageQt는 BOM 없음 · LF |
| MSVC 로컬 빌드 | `C:/Program Files/Microsoft Visual Studio/18/Community/VC/Auxiliary/Build/vcvars64.bat`를 부른 뒤 프리셋 사용, `QTDIR=D:/Qt/6.11.2/msvc2022_64` |
| 배치 파일 작성 | `printf`로 쓰지 않는다 — 경로의 `\18`을 8진수로 해석해 경로가 깨진다. Write 도구로 쓴다 |
| CI 결과 확인 | 푸시 직후 "최근 실행"을 조회하면 이전 실행을 볼 수 있다 → **커밋 해시로** 실행을 찾는다. job 상태가 실행 상태보다 늦게 반영될 수 있다 → 모든 job이 completed일 때까지 확인한다 |
| 음성 테스트 | "실패해야 하는" 확인은 실패 원인이 의도한 것인지 로그로 본다. 환경 문제로 실패한 것을 성공으로 오인하지 않는다 |
| SageSDI 원본 사실 | 주제 파일의 경로 · 줄 번호는 작성 시점(2026-09-24) 기준이다. 착수 시 다시 확인한다 |
