# 기술부채 로그 가드 (debt-log-guard)

## 목적

코드 작업이 끝난 직후, **이번 작업 범위 밖이라 남겨둔 위험 요소**를 놓치지 않도록
검토하고 `docs/DEBT_LOG.md`에 기록한다.

핵심은 부채를 **지금 전부 해결하는 것이 아니다.** 지금 고치면 작업 범위가 흐려지거나
별도 검증이 필요한 항목을, 나중에 다시 찾을 수 있도록 명시적으로 남기는 것이다.
"동작은 하지만 찝찝한 부분"을 기억에서 흘려보내지 않는 게 이 Skill의 전부다.

## 언제 동작하는가

방금 끝낸 작업이 아래에 해당하면 검토를 수행한다.

- 리팩터링, 버그 수정, API 변경, 구조/아키텍처 변경
- 테스트·빌드·린트를 **못 돌렸거나 일부만** 검증한 작업
- 새 기능 추가나 기존 로직 수정

다음 경우에는 동작하지 않는다 (검토를 건너뛴다).

- 오타 수정, 주석만 수정, 포맷팅/들여쓰기만 변경
- 문서(.md)만 수정

판단이 애매하면 "이 변경으로 나중에 누가 발목 잡힐 여지가 있나?"를 기준으로 삼는다.
없으면 건너뛴다. 과잉 기록은 로그를 노이즈로 만들어 오히려 신뢰를 떨어뜨린다.

## 판단 체크리스트

작업 결과를 두고 다음을 점검한다. 하나라도 "예"면 기록 후보가 있다.

1. **새 부채** — 이번 변경으로 임시 구현, 하드코딩, 중복 로직, 스텁/TODO가 생겼는가?
2. **남긴 기존 부채** — 작업 중 기존 구조의 문제를 발견했지만 범위 밖이라 그냥 두었는가?
3. **검증 공백** — 테스트/빌드/린트를 못 돌렸거나 일부만 돌렸는가? 손대지 못한 경로가 있는가?
4. **패턴 불일치** — 주변 코드의 기존 패턴과 다르게 구현했는가? (예: 다른 곳은 `bool + outError`인데 여기만 예외 throw)
5. **후속 분리** — 의도적으로 다음 작업으로 미룬 항목이 있는가?

각 항목은 **위치(파일·함수)와 한 문장 이유**까지 떠올려야 진짜 기록 후보다.
막연한 불안("좀 더 깔끔할 수 있을 듯")은 기록하지 않는다.

## 분류

| 분류 | 의미 |
| --- | --- |
| `검증누락` | 테스트/빌드/린트 미실행 또는 부분 검증 |
| `임시구현` | 동작은 하지만 임시방편, 스텁, TODO |
| `하드코딩` | 설정/상수로 빠져야 할 값이 코드에 박힘 |
| `중복로직` | 같은 로직이 여러 곳에 존재 |
| `구조불일치` | 주변 패턴/컨벤션과 어긋남 |
| `기존부채` | 이번 작업과 무관하게 발견했지만 범위 밖이라 남김 |

## 위험도 기준

- `높음` — 데이터 손실·보안·크래시·잘못된 계산 등 사용자 영향이 큰 경우
- `중` — 지금 동작하지만 유지보수/확장 시 발목 잡힐 가능성
- `낮음` — 알아두면 좋은 정도, 당장 영향 없음

## 워크플로

### 1. 무엇을 바꿨는지 파악

방금 한 작업의 범위를 명확히 한다. 필요하면 변경 내역을 확인한다.

```bash
git diff --stat
git status
```

### 2. 체크리스트로 판단

위 5개 항목을 점검해 기록 후보를 추린다. 후보가 없으면 **4-b**로 간다.

### 3. 사용자에게 제안 (파일 수정 전)

찾은 항목을 표준 필드로 채운 초안을 **먼저 보여주고 확인을 받는다.** 바로 파일을 고치지 않는다.
이렇게 하면 사용자가 오탐을 걸러내거나 표현을 다듬을 수 있다.

```
다음 기술부채를 docs/DEBT_LOG.md에 기록할까요?

### [2026-09-23] 검증누락 — macOS에서 로그인 창 이동을 확인하지 못함
- 위치: ui/ui/dialogs/SageLoginDlg.cpp
- 설명: `startSystemMove()` 드래그를 Windows에서만 확인했다. macOS 실기가 없어 검증하지 못했다.
- 위험도: 중
- 후속: Mac mini 도입 후 macOS에서 확인

기록할까요? (수정/삭제할 항목 있으면 알려주세요)
```

### 4-a. 확인되면 기록

`docs/DEBT_LOG.md`에 항목을 추가한다.

- 파일이 없으면 아래 헤더와 함께 새로 만든다.
- 있으면 **`## 열린 항목` 아래 맨 위에** 새 항목을 추가한다 (최신이 위).
- 기존 항목·형식은 건드리지 않는다 (surgical).

새 파일 헤더:

```markdown
# 기술부채 로그 (DEBT_LOG)

이번 작업 범위 밖이라 남겨둔 위험 요소를 기록한다. 즉시 해결이 아니라 추적이 목적이다.
해결한 항목은 `## 해결됨` 섹션으로 옮긴다.

## 열린 항목

## 해결됨
```

항목 형식 (표준 필드):

```markdown
### [YYYY-MM-DD] 분류 — 한줄요약
- 위치: <파일경로:라인 또는 함수명>
- 설명: <무엇이/왜 부채인지 한두 문장>
- 위험도: 높음 | 중 | 낮음
- 후속: <어떻게 해소할지 한 줄>
```

날짜는 시스템의 오늘 날짜를 쓴다.

### 4-b. 부채가 없으면

`DEBT_LOG.md`를 **수정하지 않는다.** 한 줄로만 보고한다.
예: "이번 변경에서 기록할 기술부채는 없습니다. (테스트 통과, 임시/하드코딩 없음)"

## 원칙

- **추적이지 해결이 아니다.** 부채를 지금 고치라고 부추기지 않는다. 남기는 게 일이다.
- **오탐을 줄인다.** 위치와 이유를 댈 수 없으면 기록하지 않는다.
- **surgical.** DEBT_LOG.md의 기존 내용·다른 파일을 임의로 손대지 않는다.
- **사용자 확인 우선.** 항상 제안 후 기록한다.
