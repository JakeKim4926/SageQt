# 스레드 · DB 연결 · 전역 상태

`coding-design`의 상세 규칙이다. 백그라운드 작업 · DB 접근 · 앱 공통 객체가 필요할 때 읽는다. 스레드 금지 사항은 `coding-rules/references/ownership-and-threads.md`에 있다.

## 스레드 구조

### UI 스레드가 담당하는 것
- Qt 이벤트 루프
- 사용자 입력 처리
- 위젯 생성 / 배치 / 그리기
- 화면 갱신

### 백그라운드가 담당하는 것
- DB 조회
- 파일 읽기/쓰기
- 문서 처리
- 데이터 파싱 및 변환

### 결과 전달 구조

```
UI 스레드 — SageWorkflowController
   │  QtConcurrent::run(요청 값)
   ▼
백그라운드
   │  DB / 파일 / 문서 처리 — 위젯·UI 객체 접근 없음
   ▼
결과 값  QFuture<T>
   │  QFutureWatcher<T>::finished  (UI 스레드에서 발생)
   ▼
컨트롤러가 결과 값을 읽고 signal 방출 → 패널 slot에서 화면 갱신
```

- 요청과 결과는 **값**으로 주고받는다. 포인터를 스레드 너머로 넘기지 않는다
- `QFutureWatcher`는 컨트롤러가 부모로 소유한다. 컨트롤러가 먼저 파괴되면 결과는 버려진다 — 수신 창 생존을 따로 검증하지 않는다
- 진행률은 `QPromise<T>`로 보고하고 `QFutureWatcher::progressValueChanged`로 받는다
- 백그라운드 작업이 쓰는 서비스는 앱 수명 동안 살아 있어야 한다. **`main.cpp`는 이벤트 루프가 끝난 뒤, 서비스를 파괴하기 전에 실행 중인 백그라운드 작업이 끝나기를 기다린다**

### DB 연결

**DB 연결은 연 스레드에서만 쓸 수 있다** (Qt 공식 제약). `QtConcurrent`는 스레드 풀의 임의 스레드에서 작업을 돌리므로:

- 작업마다 **고유한 연결 이름**으로 연결을 열고, 작업이 끝나면 닫는다 — `infra/db/`의 RAII 연결 스코프가 이 순서를 보장한다
- 연결을 스레드 사이에서 공유하거나, 멤버로 보관해 다음 작업에서 재사용하지 않는다
- 스키마 준비(생성 · 마이그레이션)는 `main.cpp`가 이벤트 루프 시작 전에 수행한다

### 전역 상태

**전역 인스턴스와 싱글턴을 두지 않는다** (함수 안 `static` 인스턴스 포함).
DB 연결 설정(경로 · 옵션), 서비스, 인증 세션 같은 앱 공통 객체는 **`main.cpp`가 소유하고 생성자 인자로 주입한다.**
DB **연결** 자체는 스레드에 묶이므로 주입하지 않는다 — 연결 설정을 주입받은 Repository가 작업 안에서 연다.
필요한 객체를 전역에서 꺼내 쓰지 않는다 — 생성자 목록이 그 클래스의 의존성 목록이다.
